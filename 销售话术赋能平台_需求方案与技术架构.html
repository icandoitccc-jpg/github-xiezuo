销售话术赋能平台

需求方案与技术架构报告
2026年8月 · 项目筹备文档 · 供团队评估讨论

一页速览

这是什么：一个桌面端软件（Windows + macOS），帮销售团队统一管理、快速查找、一键发送话术（文字+图片+文件），并集成 AI 翻译和改写能力。

解决什么：话术不统一→答错误导客户；新人不会答→老带新成本高；转化率参差→需要可复制的标准推销流程；多语言→海外客户沟通效率低。

软件性质：桌面客户端（Electron）+ 云端后台（部署在阿里云 ECS），不是纯网站，不是浏览器插件——因为需要浮动面板、窗口检测、剪贴板控制等桌面级能力。

参考对标：客服宝（话术管理+搜索+团队共享+浮动面板+图文发送）+ AI 增强（翻译/改写/半自动推荐）。不复制快语 AI 的"自动读对话"功能（那层做不了生产级）。

核心结论：功能上完全可做，技术方案成熟，建议分 4 阶段建设。

1项目背景

我们是一支面向海外 B 端批发的销售团队，业务员每天通过微信、企业微信、WhatsApp、Facebook、千牛、1688、淘宝等平台与全球客户沟通，覆盖售前咨询、成交推进、售后处理全流程。

团队在评估"快语 AI"和"客服宝"两款客服话术工具后，发现两者的内核完全不同：

客服宝快语 AI
核心模型我搜我发（人主导）AI 帮你选（AI 主导）
有没有 AI没有，靠拼音/关键词搜索有，读对话内容自动推荐
解决什么找得慢、发得慢不知道该发什么
适合我们吗适合——我们的痛点是话术不统一、新人不会答过载——我们需要的是标准化，不是 AI 替我们回答

经讨论确认：我们的需求更接近客服宝模型（话术知识库 + 快速搜索 + 团队共享），在此基础上加 AI 翻译/改写作为增强。

2需求梳理：我们要解决什么
2.1 业务痛点
痛点具体表现影响
话术不统一同一个问题，不同业务员回答不一样，甚至互相矛盾答错误导客户，专业形象受损
新人上手慢新业务员不知道怎么回答，靠问老员工，老员工被频繁打断培训成本高，老员工效率下降
转化率参差老业务员知道怎么推进成交，新人不会，转化率差距大业绩波动，不可复制
多语言障碍全球客户说不同语言，业务员需要逐条翻译，慢且容易出错沟通效率低，可能翻译不当
找图找文件麻烦介绍产品时要发文字+产品图，图存在各种文件夹里，找起来费时每次多一个动作，多线并发时更累
经验无法沉淀老业务员离职，话术经验跟着走，新人从零开始知识资产流失
2.2 我们的诉求
  • 结构化话术知识库——把话术按"售前 / 成交推进 / 售后 / 公司通用"分级分类，拆到子场景，每条话术有标准版+多语言版
  • 快速搜索——拼音/首字母/关键词混合搜索，彩色标签一眼识别，1-2 秒找到需要的话术
  • 桌面浮动面板——一个始终置顶的小窗口，不用切换软件，随时搜话术、复制粘贴
  • 图文一起发——一条话术可以关联产品图片/文件，点一下图和文字都能发出去
  • 团队三级共享——公司话术全员可用、小组话术组内共享、私人话术个人专属
  • 多语言翻译——选一条话术，AI 一键翻译成目标语言，支持批量生成多语言版本
  • 多端同步——Windows + macOS 桌面端实时同步，改了话术另一端马上看到
  • 不需要手机端——暂时统一桌面端
3软件性质：这是什么类型的软件

桌面客户端 + 云端后台

这不是一个纯网站，也不是浏览器插件，而是一个安装在电脑上的桌面软件，配合一个云端服务器提供数据存储和 AI 服务。

桌面客户端（业务员电脑上安装）

Electron 应用 · Windows + macOS 双平台 · 一个代码库编译两端

浮动面板（置顶窗口） 窗口检测与吸附 拼音搜索 剪贴板控制 模拟键盘输入 图文发送

↕ HTTPS / WebSocket
云端后台（阿里云 ECS 服务器）

Node.js API 服务 · PostgreSQL 数据库 · 阿里云 OSS 图片/文件存储

话术数据存储 用户权限管理 实时同步 团队空间 管理后台

↕ HTTPS
外部 AI 服务（按量付费）

DeepSeek API · 翻译/改写/生成/推荐

为什么不是纯网站？因为浮动面板（始终置顶在所有窗口之上）、检测聊天窗口位置、操控剪贴板（复制图片）、模拟键盘输入（自动粘贴）这些都是操作系统桌面级能力，浏览器里的网页做不到。所以必须做成桌面客户端。
为什么不是浏览器插件？浏览器插件只能在浏览器里工作，无法检测桌面版微信/QQ 窗口，也无法做成独立的浮动窗口。桌面客户端是唯一能同时覆盖桌面端和网页端聊天软件的方案。
4功能板块设计（7 大模块）

每个模块标注了"解决什么需求"，方便团队评估优先级。

01

话术知识库管理

用途：把散落在各人手里的经验，沉淀为全团队可复用的标准资产
  • 树形分类结构：售前 / 成交推进 / 售后 / 公司通用 → 子分类 → 具体话术
  • 每条话术包含：标题、正文内容、彩色标签、关联图片/文件、多语言版本
  • 话术增删改查，支持富文本编辑（加粗、列表、换行等）
  • 话术版本历史：谁改了什么、什么时候改的，可回退
  • 使用次数统计：哪条话术最常用，哪条没人用
解决：话术不统一、经验无法沉淀、老员工离职知识流失
02

智能搜索系统

用途：1-2 秒内找到需要的话术，不用记全名，不用切窗口
  • 拼音搜索：打"chanpin"或"cp"都能匹配到"产品卖点"
  • 首字母搜索：打"cpwy"匹配"产品卖点话术"
  • 中文关键词：直接打"运费""退货""最小起订量"
  • 混合搜索：拼音+中文+首字母可以混着打
  • 彩色标签筛选：红色=售后、绿色=售前、蓝色=产品、橙色=成交推进，一眼识别
  • 分类树浏览：不想搜就沿树点进去找
  • 最近使用 / 收藏夹：常用话术一秒调出
解决：找话术慢、新人不知道搜什么关键词
03

桌面浮动面板

用途：不用切软件，话术面板随时在手边，聊天窗口旁边直接操作
  • 始终置顶：面板浮在所有窗口之上，不会被聊天窗口挡住
  • 自由拖动：拖到屏幕任意位置，不影响工作
  • 窗口吸附（增强）：自动检测微信/QQ/WhatsApp 等聊天窗口，面板贴在旁边，窗口移动面板跟着移动
  • 快捷键呼出：按一个快捷键（如 Ctrl+`）面板弹出/隐藏
  • 搜索栏内置：面板里直接搜，不用打开主窗口
  • 缩略图预览：带图片的话术显示缩略图
解决：多线并发时来回切窗口的精神内耗、操作效率低
04

图文一键发送

用途：点一下，文字和图片都发出去，不用分别找字和找图
  • 每条话术可关联多张图片（产品图、细节图、场景图）和文件（PDF报价单、产品手册等）
  • 默认模式（手动复制）：点话术→文字到剪贴板→Ctrl+V粘贴；点缩略图→图片到剪贴板→Ctrl+V粘贴。100%稳定，不挑平台
  • 增强模式（自动粘贴）：点一下→程序自动粘文字→自动粘图片→模拟回车。和客服宝一样的"一键发出"体验
  • 两种模式随时一键切换，增强模式遇到不兼容的输入框可秒切回默认
解决：介绍产品时要分别找字和找图、操作步骤多
05

团队协作与权限

用途：全团队用同一套话术，新人能查到标准答案，但敏感话术可控
  • 三级话术空间：
    公司话术——全员可见，管理员维护，保证统一标准
    小组话术——按部门/产品线分组，组内共享
    私人话术——只有作者自己看到，个人收藏/草稿
  • 角色权限：管理员（全权）、编辑者（可改本组话术）、查看者（只能看和用）
  • 实时同步：任何一端改了话术，其他端几秒内刷新
  • 操作日志：谁加了/改了/删了哪条话术，有记录
解决：话术不统一、新人培训成本高、经验不可复制
06

AI 增强层

用途：AI 不替你决定发什么，而是帮你翻译、改写、补缺口
  • 一键翻译：选一条话术，指定目标语言，AI 翻译。支持英/日/西/阿/法/俄等主流语言
  • 话术改写/地区适配：同一条话术，日本客户要正式措辞，美国客户要直接口语，AI 调语气
  • 半自动推荐：把客户问的一句话粘贴进来，AI 从话术库里找匹配的排好序
  • 兜底生成：库里没覆盖的问题，AI 生成草稿，确认后可存入库
  • 批量多语言变体：一条中文话术，AI 一次性生成 5 个语言版本
  • 知识缺口检测：AI 分析哪些客户问题库里没覆盖，提醒管理者补话术
解决：多语言翻译慢且不准、话术需要按地区适配、知识库有缺口但没人发现
07

管理后台

用途：管理者维护话术质量、监控使用情况、控制 AI 成本
  • 用户管理：添加/删除业务员账号，分配角色和小组
  • 使用统计：每天发了多少话术、哪条最常用、哪些没人用、搜索失败记录
  • 话术质量审计：过期话术提醒、重复话术检测
  • AI 用量监控：翻译/生成调用次数和费用
  • 数据导出：话术库可导出为 Excel/JSON 备份
解决：没有管理视角、话术质量无人维护、AI 成本不可控
5技术实现方案
5.1 技术选型
组件技术方案为什么选它
桌面客户端Electron + React + TypeScript一套代码编译 Windows + macOS；生态成熟；剪贴板/窗口控制库丰富
后端 APINode.js + Express/Fastify与前端同语言，开发效率高；WebSocket 原生支持
数据库PostgreSQL支持全文搜索、JSON 字段（话术结构灵活）、成熟稳定
图片/文件存储阿里云 OSS按量付费、CDN 加速、与 ECS 同机房传输快
实时同步WebSocket话术改动即时推送到所有在线客户端
拼音搜索pinyin-pro（npm 库）成熟方案，支持全拼/首字母/混合，不需要从零开发
窗口检测active-win / get-windows跨平台库，检测当前活动窗口标题和位置
模拟输入nut.js / robotjs模拟键盘粘贴（Ctrl+V）和回车，跨平台
AI 服务DeepSeek API性价比高（约0.01元/条调用），中文能力强
5.2 部署方案
部署组件部署位置说明
后端 API + 数据库阿里云 ECS团队已有 ECS 服务器（现跑 ERP 系统）。可在同一台服务器上部署（如资源够），也可新开一台（建议 2核4G 起步，约 100-200元/月）
图片/文件存储阿里云 OSS按存储量+流量计费，初期约几元/月
桌面客户端每个业务员电脑打包成 .exe（Windows）和 .dmg（macOS），提供下载链接安装
AI 服务DeepSeek 云端 API外部服务，按调用量付费，不需要自己部署
域名（可选）需购买如果要让客户端通过域名访问后台（而非IP），需买一个域名+SSL证书
关于服务器：你们已经有一台阿里云 ECS 在跑 ERP 系统。这个话术平台的后端可以和 ERP 共用一台服务器（只要 ERP 没把资源吃满），省一台机器的钱。如果担心互相影响，新开一台 2核4G 的 ECS 大概 100-200 元/月。
5.3 安全性
  • 数据传输加密：客户端与服务器之间全 HTTPS 加密
  • 用户认证：账号密码登录 + JWT Token，不支持匿名访问
  • 权限隔离：私人话术只有作者能看，小组话术只有组成员能看
  • 数据备份：数据库每日自动备份，话术库可随时导出
  • AI 数据安全：发送给 DeepSeek 的只有话术文本，不含客户隐私信息
6分阶段建设计划

不要一口气全做——先跑通核心流程，团队用起来再逐步加功能。

第一阶段
最小可用版

目标：能存话术、能搜到、能复制粘贴

  • 话术知识库 CRUD + 树形分类
  • 拼音/关键词搜索 + 彩色标签
  • 桌面浮动面板（置顶 + 手动复制模式）
  • 三级权限（公司/小组/私人）
  • AI 一键翻译
  • Windows + macOS 双端
第二阶段
核心体验版

目标：和客服宝一样的使用体验

  • 窗口吸附（检测聊天窗口 + 面板跟随）
  • 图文一键发送（默认模式）
  • 自动粘贴增强模式
  • 文件附件支持（PDF/文档）
  • AI 话术改写/地区适配
  • 收藏夹 + 最近使用
第三阶段
团队赋能版

目标：AI 主动辅助 + 管理视角

  • AI 半自动推荐
  • AI 兜底生成 + 存入知识库
  • 批量多语言变体生成
  • 使用统计与分析
  • 知识缺口检测
  • 管理后台完善
第四阶段
持续优化

目标：根据实际使用反馈迭代

  • 更多平台窗口适配
  • 话术审批工作流
  • 数据看板/报表
  • 性能优化
  • （如有需要）手机端 PWA
7买现成 vs 自己做：决策对比
买客服宝 自己做
初期成本 专业版按人/年付费，3人团队约几百元/年 开发积分消耗（较高，但一次性）+ 服务器约100-200元/月
功能匹配度 80% 匹配——话术管理、搜索、吸附、图文发送都有；但没有多语言翻译，海外 B2B 场景缺关键能力 100% 定制——话术树按你们的售前/成交/售后/公司通用结构来，翻译是核心功能不是附加
多语言能力 没有——客服宝没有 AI，不能翻译 核心功能——DeepSeek 一键翻译+改写+批量多语言变体
数据控制权 话术存在客服宝的云上，不在你们手里 话术存在自己的服务器上，完全可控，可导出
定制灵活性 固定功能，不能改，不能加你们要的"成交推进流程话术树" 完全可定制——话术分类、标签体系、权限结构都按你们业务来
维护成本 零维护——客服宝团队负责更新 需要有人维护服务器、跟进口碑反馈迭代
上手速度 下载安装即用 需等开发完成（第一阶段可较快交付）
长期成本 持续付费，人数越多越贵 服务器费+AI调用费，与人数无关，团队扩大不增加成本
AI 运行成本 不适用（没有AI） DeepSeek API 约 0.01元/条，日500条约 150元/月
关键差异：客服宝没有 AI 翻译——而多语言是你们海外 B2B 业务的第一刚需。如果买客服宝，翻译还得用别的工具单独做，流程割裂。自己做的话翻译是内置的，选话术→一键翻译→发送，一气呵成。
8待团队讨论决定的事项
  1. 买还是做？核心判断点：多语言翻译对你们有多重要？如果重要→客服宝满足不了→自己做；如果不重要→客服宝够用→买。
  2. 如果做，第一阶段范围确认：上面列的"最小可用版"6 项功能，有没有要加的或砍的？
  3. 服务器方案：和 ERP 共用一台 ECS，还是新开一台？
  4. 话术分类体系：售前/成交推进/售后/公司通用 这四个一级分类够不够？要不要再细化？谁来负责初始话术录入？
  5. 用户角色：谁是管理员？分几个小组？每个小组谁能编辑话术？
  6. AI 使用策略：翻译/改写/生成都开放给所有业务员用，还是只有部分功能开放？需不需要设每人的 AI 调用上限？
