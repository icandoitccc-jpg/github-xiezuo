Claude Code 原生支持 AGENTS.md：通用项目指令文件开始替代 CLAUDE.md

AI Coding / 工具链标准

9 月 19 日，Anthropic 在 Claude Code 2.1.277 中加入原生 AGENTS.md 读取能力：当项目目录没有 CLAUDE.md 时，Claude Code 会自动读取 AGENTS.md 作为项目指令；用户也可以在 /config 的 "Project instructions" 里手动切换。Reddit 用户发现 Anthropic 的 claude-code 仓库里已出现 mods/agents-md 目录，且 Anthropic 把对应 mod 开源了出来。这意味着同一套项目指令文件可以同时喂给 Claude Code 和其他兼容的 coding agent，而不再被厂商私有命名锁住。

此前 Shopify CEO 曾公开威胁因 CLAUDE.md 的品牌锁定而禁用该工具，社区也一直用软链接或脚本做兼容。现在开发者有机会删掉冗余配置，实现一套指令跨平台通用。当然，"一套指令是否完美适配所有模型"仍有争议，但在实际工程中，降低工具切换成本的优先级远高于针对某一模型 token 权重的微调。

Why it matters：这是一次典型的"协议层权力转移"——AI 工具竞争从"我的模型更强"下沉到"谁定义开发者的工作流文件格式"。AGENTS.md 若能成为事实标准，将让 coding agent 的切换成本接近零，模型厂商的护城河会从"私有指令格式"转向"执行质量与安全性"。对团队而言，现在就可以把项目级 agent 指令写成 AGENTS.md，避免被单一工具锁定；这也预示着 .agents/skills 等目录的标准化拉锯才刚刚开始，生态定义权之争会愈演愈烈。

MiniMax 开源 MIT 终端编码智能体：代码、TUI、沙盒、MCP 全开放

AI Coding / 开源生态

MiniMax 在 GitHub 发布了终端编码智能体 MiniMax Code 0.4.12 的源码预览，第一方代码采用 MIT 协议。功能覆盖交互式 TUI 与 headless 执行、代码编辑、shell 调用、diff 与测试验证、权限与沙盒、Plan Mode 与可恢复会话、子代理 / 插件 / skills / MCP，还支持 BYOK（可接入 OpenAI、Anthropic 等第三方模型）以及 ACP 编辑器。

发布时间耐人寻味：正值社区热议"coding agent 到底读了什么、发了什么、存了什么"之际，MiniMax 选择把 agent 层完全开源，让外部可以审计其数据边界与执行逻辑。这也让它成为国内第一家把完整终端编码 agent 开放给开发者的大模型公司。

Why it matters：coding agent 的竞争开始分化为两条路线：闭源性能型（Cursor、Claude Code、Codex）与开源可审计型。MiniMax 的开源动作直接回应了企业部署时最大的顾虑——"agent 会不会把我的代码上传到云端"。对需要私有化或 air-gapped 部署的团队，BYOK + 可审计代码 + MCP 的组合降低了试用门槛；对生态而言，它也把"技能 / MCP / 项目指令"这些中间层标准往前推了一步。如果开源 agent 在接下来半年能把体验追到闭源产品的 80%，企业采购的决策权重可能会从"模型品牌"转向"可控性与集成成本"。

罗技 MX 键盘为 AI 编程 Agent 设物理快捷键：Copilot / Claude Code 一键直达

AI Coding / 硬件入口

罗技推出面向 agentic coding 场景的 MX 键盘，配备 9 个可编程按键和一块动态显示屏，可一键调用 GitHub Copilot、Claude Code 等 AI 编程智能体，并实时显示 Agent 当前状态（例如正在运行、需要确认、已完成）。它的设计目标很明确：减少开发者在编辑器、终端与 AI 助手之间来回切换的摩擦，把物理按键变成 AI 工作流的直接入口。

这是主流外设厂商第一次为"AI 编程 Agent"专门设计硬件入口。过去调用 AI 助手的动作平均需要 2–3 秒（找图标、记快捷键、打开面板），而 MX 键盘把它压缩到按一个键。当 coding agent 从"偶尔用一下"变成"整天开着"的工作流时，这种时间节省会指数级放大。

Why it matters：硬件开始为 AI 工作流重新设计，说明 agentic coding 已经从早期尝鲜进入"生产力默认配置"阶段。罗技此举可能引发一波"AI 外设"创新潮——未来键盘、鼠标、Stream Deck、甚至耳机都可能成为 Agent 的状态显示与确认入口。对企业来说，这意味着 AI coding 的部署不仅要考虑软件和模型选型，还要考虑人机交互硬件的升级；对安全团队来说，物理快捷键也带来新的问题：如果一键就能让 Agent 执行高危操作，拦截和审计机制必须跟得上。

丰田宣布全球 60 座工厂部署 40 万台机器人，ELEY 两周学会叠 T 恤

Embodied Intelligence / 工业落地

丰田宣布将在全球约 60 座工厂部署 40 万台机器人（15 万台自用 + 25 万台集团企业），2028 年起每年投入约 1 万亿日元（约 67 亿美元） 用于工厂改造。核心机型 ELEY（Embodied Learning robot for Enhanced Yield）是一款双指人形机器人，重约 50 公斤，采用轮式底盘而非双腿，搭载丰田研究院的 Large Behavior Models。

在演示中，ELEY 经过约 两周、1,500 次重复观察工人动作，以近乎完美的准确率学会折叠 T 恤；学到的技能可以推送至其他工厂的同型机器人。丰田的差异化在于"人穿工具示范 → 机器人观察学习"的闭环——不依赖昂贵的遥操作数据，而是让机器人从人类日常动作中直接学习。

Why it matters：这是全球最大规模的工业机器人部署计划之一。40 万台量级意味着具身智能从"实验室 demo"正式进入"制造业基础设施"阶段。ELEY 的"观察学习"路线尤其值得关注：它绕过了当前行业最大的瓶颈之一——遥操作数据稀缺与成本高。如果丰田能把"人类示范 → 技能提炼 → 跨工厂同步"的流水线跑通，具身智能的落地路径会从"每家公司自己采集数据"转向"共享行为模型 + 本地少量微调"，大幅压低规模化门槛。2027–2028 年将成为验证这套方法论能否跨工厂复制的关键窗口。

智平方 AlphaBot O1 强调"可复制"商业化：从"能干活"到标准化交付

Embodied Intelligence / 商业化路径

智平方在广州中博会上展示新一代全身协同通用智能机器人 AlphaBot O1，由自研具身大模型 AlphaBrain 驱动，支持双臂力控、全身协同、跨空间长序列与精细操作。公司同时公布的重点不是动作能力，而是可复制、可规模化的交付能力：机器人已进入半导体显示、汽车制造、生物医药、公共服务、新零售等场景，"机器人店员"已在全国 10 余个省市常态化运营，并有项目进入批量部署。

智平方下一阶段的目标是"从能干活到可复制"——把真实数据采集、数据管线、轻量化模型适配、仿真与实机评测、远程操控与异常恢复、软件部署与运维等能力提前平台化；进入新场景后只做增量数据采集、模型适配和少量配置调整。公司负责人把这套方法概括为"机器人能力 + 场景经验 + 数据闭环"，并表示成熟后会向海外市场复制。

Why it matters：具身智能行业不缺"会翻跟头的机器人"，缺的是"能在客户现场连续稳定运行、算得出 ROI、跨场景迁移"的方案。智平方把判断标准从动作完成度转移到工作时长、任务效率、稳定运行时间、人工替代效果、投入产出周期，这正对应制造业客户采购设备时的真实决策逻辑。它的"通用底座 + 快速适配"路线也给出了行业可复制路径：先把从数据到部署的完整流水线平台化，再用已验证的行业流程去迁移新场景。如果这套模式跑通，2026–2027 年可能是中国具身智能从"单点试点"转向"批量交付"的拐点。
