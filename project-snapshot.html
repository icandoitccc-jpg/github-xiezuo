Project Background

This project is not about getting orders immediately. It is not about brand building. It is about validating whether ShineTrip can enter the US B2B Outdoor market through real market development.

The entire project follows a Validation mindset, not a traditional foreign trade development mindset.

Core Objective: Obtain the first batch of real responses from US Independent Outdoor Retailers. A "response" includes: Email reply, Facebook Messenger reply, Instagram reply, LinkedIn reply (once restored). Response is the KPI — not conversion.

Buyer Operating System (BOS) v1.1

Codex has completed Multi-Channel Buyer Acquisition SOP v1.0, formalized in the BOS (Buyer Operating System) v1.1 Excel workbook.

BOS = 五大表 (Data Layer) + Buyer SOP (Action Layer)

BOS Core Components

  • Dashboard — Boss view funnel: Customers → Email Sent → Email Reply → Messenger Sent → Messenger Reply → First Conversation
  • Buyer Intelligence DB — Multi-channel buyer data: Facebook, Instagram, LinkedIn, Owner visibility, Last post, Community activity, Email status
  • Touch Sequence — Standardized touch schedule: Day0 Email → Day2 FB Research → Day3 Like → Day5 Messenger → Day7 Follow-up Email
  • Buyer Accessibility Score — 10-point model: Facebook (2) + Instagram (2) + LinkedIn (2) + Email (2) + Owner visibility (2). Priority: 8-10 High, 5-7 Medium, 0-4 Low
  • SOP & Rules — 7-stage SOP: Account Warm-up → Industry Ecosystem → Buyer Intelligence → Touch Sequence → Accessibility Score → Feed Strategy → Absolute No

Project Snapshot Rule

Fixed Rule: Any decision that affects project direction, SOP, process, or database structure must produce an updated Project Snapshot. Do not wait until information desync is discovered to fix it.

This ensures GitHub always has the latest "project state." WorkBuddy maintains it, Codex executes, Chen judges direction. Even if an AI is decommissioned or replaced, the project never loses context because of a "memory gap."

This mechanism is more valuable than adding any new AI.
