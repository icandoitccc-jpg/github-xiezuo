一页速览

这是什么：一个桌面端软件（Electron），帮销售团队统一管理、快速查找、一键发送话术（文字+图片+文件），并集成 AI 翻译和改写能力。

解决什么：话术不统一→答错误导客户；新人不会答→老带新成本高；转化率参差→需要可复制的标准推销流程；多语言→海外客户沟通效率低；找图找文件→操作步骤多。

软件性质：桌面客户端（Electron）+ 云端后台（阿里云 ECS），不是纯网站也不是浏览器插件——因为需要浮动面板、窗口检测、剪贴板控制等桌面级能力。

参考对标：客服宝模型（话术管理+搜索+团队共享+浮动面板+图文发送）+ AI 增强（翻译/改写/半自动推荐）。不复制快语 AI 的"自动读对话"功能。

当前阶段：团队已确认方向，下一步是技术验证（PoC）——先在 macOS 上做一个最小可运行版本，证明能力后再进入正式开发。不承诺日历工期，以验收关卡为准。

核心决策：放弃快语 AI 的"四层吸附"（做不了生产级），采用客服宝的"两层吸附"（物理贴靠+模拟发送，可做）。第一版先做 Windows 或 macOS 单端验证，不贪双端。

1决策历程：我们是怎么走到这一步的

这一节记录了团队的完整决策路径。如果将来需要交接，新接手者通过这节可以理解"为什么做了这些选择"。

第一步
调研快语 AI 和客服宝
同事前公司用过客服宝，推荐了这个方向。网上对比发现快语 AI 营销排名靠前。经深入调研发现两者内核完全不同——客服宝没有 AI，靠拼音/关键词搜索，是"我搜我发"模型；快语 AI 有 AI 读对话自动推荐，是"AI 帮你选"模型。
第二步
拆解"吸附"功能，发现四层技术
"吸附"不是一个功能，是四层：①物理贴靠（找窗口+贴旁边+跟着动）→ ②读对话内容（UI Automation）→ ③AI 自动匹配（大模型推荐）→ ④模拟发送（自动粘贴+回车）。快语四层都做，客服宝只做①+④。第②层是技术壁垒——需要逐个逆向每个 App 的窗口结构，微信一更新就可能失效。
第三步
明确业务需求，发现品类不同
团队是海外 B2B 批发销售，痛点是话术不统一、新人不会答、转化率参差、多语言障碍。这些痛点的核心不是"打字慢"（快语解决的），而是"答得对、答得统一、新人能上手"（客服宝模型解决的）。品类从"快捷回复工具"重判为"销售话术赋能平台（Sales Enablement）"。
第四步
确认客服宝模型 + AI 增强
放弃快语 AI 的第②③层（读对话+自动推荐），保留客服宝的第①④层（物理贴靠+模拟发送），在此基础上加 AI 翻译/改写/半自动推荐。AI 角色从"替你决定发什么"变成"帮你处理你选的话术"。
第五步
加入图文功能需求
业务员介绍产品时需要发文字+产品图，当前流程是搜话术粘贴 + 去文件夹翻图两个分散动作。确认话术可关联多张图片/文件，点一下复制到剪贴板。系统剪贴板同一时间只能放文字或图片，但程序可以快速切换（先粘图再粘字），用户感觉是"一键发出"。
第六步
引入外部评估（ChatGPT），接受修正
因积分顾虑，让 ChatGPT 在 WorkBuddy 和扣子之间选承接方。ChatGPT 选择 WorkBuddy（Electron 桌面开发能力强），但提出重要修正：①第一阶段写得太大应再砍；②自动粘贴是高风险不应放第一版；③窗口吸附比说的更难；④不要信工期承诺要用验收关卡；⑤先做技术验证再谈正式开发。WorkBuddy 接受全部修正。
当前状态
准备技术验证（PoC）
方案已确定，下一步是先做一个可运行的技术验证版本。ChatGPT 建议 PoC 做 Windows .exe，但 WorkBuddy 运行在 macOS 上无法本地打包 Windows .exe，建议 PoC 先在 macOS 上做（能实际运行测试），Windows 打包问题等验证通过后用 GitHub Actions 解决。

2.1 基本信息对比
客服宝快语 AI
开发商深圳千百尺网络科技深圳西部港湾科技
有没有 AI没有——纯拼音/关键词搜索有——DeepSeek V4 大模型
核心模型我搜我发（人主导）AI 帮你选（AI 主导）
解决什么痛点找得慢、发得慢不知道该发什么
吸附层数2 层（物理贴靠 + 模拟发送）4 层（+ 读对话内容 + AI 自动匹配）
多语言翻译没有有（AI 翻译，100+ 语言）

2.2 "吸附"功能四层拆解

这是整个项目最关键的技术理解——"吸附"不是一个功能，是四层技术的叠加：

层级做什么谁用了能不能做
第1层物理贴靠：找到聊天窗口位置，把面板贴旁边，窗口移动面板跟着移动。用 Win32 API（Windows）或 Accessibility API（macOS）客服宝 + 快语能做
第2层读对话内容：用 UI Automation API 把聊天窗口里的文字读出来。需要逐个逆向每个 App 的窗口结构，App 更新就可能失效仅快语做不了生产级
第3层AI 自动匹配：拿第2层读到的对话文本发给大模型，从话术库推荐最匹配的。依赖第2层仅快语依赖第2层，无法独立做
第4层模拟发送：模拟键盘 Ctrl+V 粘贴话术 + 模拟回车发送。SendInput（Windows）/ CGEvent（macOS）客服宝 + 快语能做（有风险，见后文）
关键结论：我们放弃第2层和第3层（快语的 AI 自动读对话+推荐），保留第1层和第4层（客服宝的物理贴靠+模拟发送）。这不是"放弃吸附"，而是"放弃 AI 自动读对话"——物理贴靠体验保留，只是不自动猜你要发什么，靠你自己搜。
2.3 两个产品和微信/Windows 有合作吗？

没有。两家都用的是 Windows/macOS 操作系统对所有程序公开的底层 API（Win32 API / Accessibility API），不是谁给了谁授权。微信作为一个窗口，无法阻止另一个程序读取它的位置、在旁边放面板、或模拟键盘往输入框打字。

和微信/Tencent：没有官方合作，属于"灰色操作"。微信一更新 UI 结构，UI Automation 读取就可能失效（快语受此影响，客服宝不读内容所以不受影响）。

和电商平台：客服宝靠 OS 级 API 吸附桌面客户端，无官方合作。快语的电商工作台有 OAuth 授权绑定店铺，但消息交互仍是自己内嵌网页+JS 注入扒的。

3我们的业务需求
3.1 团队画像
  • 业务类型：海外 B 端批发销售
  • 客户分布：世界各地，多语言沟通
  • 使用平台：微信、企业微信、WhatsApp、Facebook、千牛、1688、淘宝
  • 业务流程：售前咨询 → 成交推进 → 售后处理，同一时间多线并发
  • 团队结构：老业务员 + 新业务员，水平参差，需要标准化
  • 设备：桌面端（Windows + macOS），暂不需要手机端
3.2 六大业务痛点
痛点具体表现影响
话术不统一同一个问题，不同业务员回答不一样，甚至互相矛盾答错误导客户，专业形象受损
新人上手慢新业务员不知道怎么回答，靠问老员工，老员工被频繁打断培训成本高，老员工效率下降
转化率参差老业务员知道怎么推进成交，新人不会，转化率差距大业绩波动，不可复制
多语言障碍全球客户说不同语言，业务员需要逐条翻译，慢且容易出错沟通效率低，可能翻译不当
找图找文件麻烦介绍产品时要发文字+产品图，图存在各种文件夹里，找起来费时每次多一个动作，多线并发时更累
经验无法沉淀老业务员离职，话术经验跟着走，新人从零开始知识资产流失
3.3 八项具体诉求
  1. 结构化话术知识库——按"售前 / 成交推进 / 售后 / 公司通用"分级分类，拆到子场景，每条话术有标准版+多语言版
  2. 快速搜索——拼音/首字母/关键词混合搜索，彩色标签一眼识别，1-2 秒找到需要的话术
  3. 桌面浮动面板——一个始终置顶的小窗口，不用切换软件，随时搜话术、复制粘贴
  4. 图文一起发——一条话术可以关联产品图片/文件，点一下图和文字都能发出去
  5. 团队三级共享——公司话术全员可用、小组话术组内共享、私人话术个人专属
  6. 多语言翻译——选一条话术，AI 一键翻译成目标语言，支持批量生成多语言版本
  7. 多端同步——Windows + macOS 桌面端实时同步，改了话术另一端马上看到
  8. 不需要手机端——暂时统一桌面端
3.4 品类重判：这不是"快捷回复工具"，是"销售话术赋能平台"

去掉快语的"AI 自动读对话"后，我们要做的东西，品类已经从"快捷回复工具"（快语/客服宝的品类）变成了"销售话术赋能平台（Sales Enablement）"。

区别在于：

快捷回复工具（客服宝/快语）销售话术赋能平台（我们的方向）
解决什么打字慢、发得慢答得对、答得统一、新人能上手、转化能复制
核心价值省打字时间把老业务员的经验沉淀成全团队可复用资产
谁主导人搜人发（或 AI 替你选）人主导，AI 辅助（翻译/改写/补缺口）
对标产品客服宝、快语Mindtickle、Highspot、Seismic、HubSpot Sales Hub

这意味着：平台不重要了（因为只是复制粘贴，跟用哪个聊天软件无关），核心是那套结构化、可检索、团队共享、多语言的话术知识库。

4软件性质：这是什么类型的软件

桌面客户端 + 云端后台

这不是一个纯网站，也不是浏览器插件，而是一个安装在电脑上的桌面软件，配合一个云端服务器提供数据存储和 AI 服务。

桌面客户端（业务员电脑上安装）

Electron 应用 · Windows + macOS 双平台 · 一套代码编译两端

浮动面板（置顶窗口） 窗口检测与物理贴靠 拼音搜索 剪贴板控制 模拟键盘输入 图文发送

↕ HTTPS / WebSocket
云端后台（阿里云 ECS 服务器）

Node.js API 服务 · PostgreSQL 数据库 · 阿里云 OSS 图片/文件存储

话术数据存储 用户权限管理 实时同步 团队空间 管理后台

↕ HTTPS
外部 AI 服务（按量付费）

DeepSeek API · 翻译/改写/生成/推荐

为什么不是纯网站？浮动面板（始终置顶）、检测聊天窗口位置、操控剪贴板（复制图片）、模拟键盘输入（自动粘贴）都是操作系统桌面级能力，浏览器网页做不到。所以必须做成桌面客户端。
为什么不是浏览器插件？浏览器插件只能在浏览器里工作，无法检测桌面版微信/QQ 窗口，也无法做成独立的浮动窗口。桌面客户端是唯一能同时覆盖桌面端和网页端聊天软件的方案。
5功能板块设计（7 大模块）

每个模块标注了"解决什么需求"和"属于哪个建设阶段"。

01

话术知识库管理

用途：把散落在各人手里的经验，沉淀为全团队可复用的标准资产
  • 树形分类结构：售前 / 成交推进 / 售后 / 公司通用 → 子分类 → 具体话术
  • 每条话术包含：标题、正文内容、彩色标签、关联图片/文件、多语言版本
  • 话术增删改查，支持富文本编辑（加粗、列表、换行等）
  • 话术版本历史：谁改了什么、什么时候改的，可回退
  • 使用次数统计：哪条话术最常用，哪条没人用
解决：话术不统一、经验无法沉淀、老员工离职知识流失 · 阶段0+1
02

智能搜索系统

用途：1-2 秒内找到需要的话术，不用记全名，不用切窗口
  • 拼音搜索：打"chanpin"或"cp"都能匹配到"产品卖点"
  • 首字母搜索：打"cpwy"匹配"产品卖点话术"
  • 中文关键词：直接打"运费""退货""最小起订量"
  • 混合搜索：拼音+中文+首字母可以混着打
  • 彩色标签筛选：红色=售后、绿色=售前、蓝色=产品、橙色=成交推进，一眼识别
  • 分类树浏览：不想搜就沿树点进去找
  • 最近使用 / 收藏夹：常用话术一秒调出
解决：找话术慢、新人不知道搜什么关键词 · 阶段0+1
03

桌面浮动面板

用途：不用切软件，话术面板随时在手边，聊天窗口旁边直接操作
  • 始终置顶：面板浮在所有窗口之上，不会被聊天窗口挡住
  • 自由拖动：拖到屏幕任意位置，不影响工作
  • 全局快捷键：按一个快捷键（如 Ctrl+`）面板弹出/隐藏
  • 搜索栏内置：面板里直接搜，不用打开主窗口
  • 缩略图预览：带图片的话术显示缩略图
  • 窗口物理贴靠（后期增强）：自动检测聊天窗口，面板贴旁边跟着移动
解决：多线并发时来回切窗口的精神内耗、操作效率低 · 阶段0+1（贴靠在阶段2）
04

图文一键发送

用途：点一下，文字和图片都能复制/发送，不用分别找字和找图
  • 每条话术可关联多张图片（产品图、细节图、场景图）和文件（PDF报价单、产品手册等）
  • 默认模式（复制到剪贴板）：点话术→文字到剪贴板→Ctrl+V粘贴；点缩略图→图片到剪贴板→Ctrl+V粘贴。100%稳定，不挑平台
  • 增强模式（自动粘贴）：点一下→程序自动粘文字→自动粘图片→模拟回车。和客服宝一样的"一键发出"体验
  • 系统剪贴板同一时间只能放一种（文字或图片），增强模式下程序快速切换两次
  • 两种模式随时一键切换，增强模式遇到不兼容的输入框可秒切回默认
解决：介绍产品时要分别找字和找图、操作步骤多 · 阶段1（复制） 阶段2（自动粘贴）
05

团队协作与权限

用途：全团队用同一套话术，新人能查到标准答案，但敏感话术可控
  • 三级话术空间：公司话术（全员可见，管理员维护）/ 小组话术（按部门/产品线分组，组内共享）/ 私人话术（只有作者自己看到）
  • 角色权限：管理员（全权）、编辑者（可改本组话术）、查看者（只能看和用）
  • 实时同步：任何一端改了话术，其他端几秒内刷新
  • 操作日志：谁加了/改了/删了哪条话术，有记录
解决：话术不统一、新人培训成本高、经验不可复制 · 阶段1（公司+私人） 阶段2（小组+实时同步）
06

AI 增强层

用途：AI 不替你决定发什么，而是帮你翻译、改写、补缺口
  • 一键翻译：选一条话术，指定目标语言，AI 翻译。支持英/日/西/阿/法/俄等主流语言
  • 话术改写/地区适配：同一条话术，日本客户要正式措辞，美国客户要直接口语，AI 调语气
  • 半自动推荐：把客户问的一句话粘贴进来，AI 从话术库里找匹配的排好序
  • 兜底生成：库里没覆盖的问题，AI 生成草稿，确认后可存入库
  • 批量多语言变体：一条中文话术，AI 一次性生成 5 个语言版本
  • 知识缺口检测：AI 分析哪些客户问题库里没覆盖，提醒管理者补话术
解决：多语言翻译慢且不准、话术需要按地区适配、知识库有缺口但没人发现 · 阶段1（翻译） 阶段2-3（其余）
07

管理后台

用途：管理者维护话术质量、监控使用情况、控制 AI 成本
  • 用户管理：添加/删除业务员账号，分配角色和小组
  • 使用统计：每天发了多少话术、哪条最常用、哪些没人用、搜索失败记录
  • 话术质量审计：过期话术提醒、重复话术检测
  • AI 用量监控：翻译/生成调用次数和费用
  • 数据导出：话术库可导出为 Excel/JSON 备份

6.3 安全性
  • 数据传输加密：客户端与服务器之间全 HTTPS 加密

7已知技术风险与对策

风险等级对策
macOS 要手动授权辅助功能中Mac 的安全机制要求用户在"系统设置→隐私与安全性→辅助功能"里勾选应用。一次性操作，安装时引导用户完成

模拟粘贴被某些输入框拒绝高设计双模式：默认"复制到剪贴板"（100%稳定），增强"自动粘贴"（不兼容时切回默认）。不要把"所有平台通用一键发送"当承诺
剪贴板同一时间只能放文字或图片中增强模式下程序快速切换两次（先粘图再粘字），间隔 100-200ms。用户感觉是"一键发出"
窗口吸附涉及多显示器/屏幕缩放/全屏/焦点竞争高吸附放在第二阶段，不放进 PoC 和第一阶段。逐个处理边界情况，不追求"一招通吃"
Windows .exe 打包在 macOS 上做不了中方案1：GitHub Actions 配 Windows 构建环境。方案2：找一台 Windows 机器做打包。PoC 阶段先做 macOS .dmg
应用签名和公证（macOS notarization / Windows code signing）中需购买开发者证书。未签名的应用会被系统安全提示拦截，但不影响功能。正式发布前处理
自动更新机制低Electron 有 electron-updater 方案，后期集成
多人同时编辑同一条话术的冲突低乐观锁 + 版本号，编辑冲突时提示用户
AI 调用成本不可控中设每人/每日 AI 调用上限，管理后台监控用量

10买现成 vs 自己做：决策对比
买客服宝 自己做
初期成本 专业版按人/年付费，3人团队约几百元/年 开发积分消耗（较高，但一次性）+ 服务器约100-200元/月
功能匹配度 80% 匹配——话术管理、搜索、吸附、图文发送都有；但没有多语言翻译 100% 定制——话术树按你们的售前/成交/售后/公司通用结构来，翻译是核心功能
多语言能力 没有——客服宝没有 AI，不能翻译 核心功能——DeepSeek 一键翻译+改写+批量多语言变体
数据控制权 话术存在客服宝的云上，不在你们手里 话术存在自己的服务器上，完全可控，可导出
定制灵活性 固定功能，不能改，不能加"成交推进流程话术树" 完全可定制——分类、标签、权限都按业务来
维护成本 零维护——客服宝团队负责更新 需要有人维护服务器、跟进反馈迭代
上手速度 下载安装即用 需等开发完成（PoC 先行验证）
长期成本 持续付费，人数越多越贵 服务器费+AI调用费，与人数无关，团队扩大不增加成本
AI 运行成本 不适用（没有AI） DeepSeek API 按量付费，具体成本取决于使用量
关键差异：客服宝没有 AI 翻译——而多语言是你们海外 B2B 业务的第一刚需。如果买客服宝，翻译还得用别的工具单独做，流程割裂。自己做的话翻译是内置的，选话术→一键翻译→发送，一气呵成。
